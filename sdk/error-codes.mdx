## Overview

The SDK throws `SDKError` instances with a `code` property. Always check `err.code` to handle errors correctly.

```ts
import { SDKError } from "@gennoctua/personalize-core";

try {
  const result = await sdk.personalize({ imageUrl, productType, gender: "female" });
} catch (err) {
  if (err instanceof SDKError) {
    console.log(err.code);        // e.g. "PERSONALIZATION_JOB_TIMEOUT"
    console.log(err.message);     // human-readable description
    console.log(err.recoverable); // true = user can retry
    console.log(err.details);     // additional debug info
  }
}
```

## Error Code Reference

### `AUTH_INVALID`

| Property | Value |
|---|---|
| Recoverable | ❌ No |
| When | Token was rejected by the server |

**Causes:**
- JWT has expired (tokens last 1 hour)
- JWT was tampered with or signed with wrong secret
- Brand key (`gn_pk_...`) has been deactivated

**How to handle:**
```ts
case "AUTH_INVALID":
  // In frontend-only mode: SDK will auto-refresh the token next call
  // In full-stack mode: call getToken() to get a fresh token
  await sdk.personalize({ imageUrl, productType, gender: "female" }); // retry
  break;
```

---

### `CONFIG_INVALID`

| Property | Value |
|---|---|
| Recoverable | ❌ No |
| When | Invalid SDK configuration |

**Causes:**
- Missing required `auth` config
- `proxyUrl` is not a valid URL
- `publicKey` is missing or malformed
- `pollIntervalMs` is zero or negative

**How to handle:**
```ts
case "CONFIG_INVALID":
  // This is a developer error — check your Personalize.init() config
  console.error("Fix your SDK config:", err.message);
  break;
```

---

### `RATE_LIMITED_CLIENT`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — wait and retry |
| When | Client-side rate limiter blocked the request |

**Causes:**
- User clicked Try On too quickly (within `cooldownMs`)
- User exceeded `maxPerSession` or `maxPerProduct` limit

**How to handle:**
```ts
case "RATE_LIMITED_CLIENT":
  showMessage("Please wait a moment before trying again.");
  // Re-enable button after cooldown
  setTimeout(() => {
    tryOnButton.disabled = false;
  }, 10000);
  break;
```

---

### `RATE_LIMITED_SERVER`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — wait and retry |
| When | Server-side rate limit was hit |

**Causes:**
- Too many requests from this IP or brand
- HP capacity limit reached

**How to handle:**
```ts
case "RATE_LIMITED_SERVER":
  showMessage("Our servers are busy. Please try again in a minute.");
  break;
```

---

### `PERSONALIZATION_JOB_FAILED`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — retry |
| When | HP returned a FAILED status |

**Causes:**
- AI generation failed (no face detected in user photo, unusual image format)
- Upstream HP error
- Product image URL unreachable

**How to handle:**
```ts
case "PERSONALIZATION_JOB_FAILED":
  showMessage("Try-on failed. Try a different photo or product image.");
  tryOnButton.disabled = false;
  break;
```

**Common fix:** Ensure the user's photo has a clear, front-facing face and the product image URL is publicly accessible.

---

### `PERSONALIZATION_JOB_TIMEOUT`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — retry |
| When | Generation exceeded `pollMaxAttempts × pollIntervalMs` (default: 3 minutes) |

**Causes:**
- HP is under heavy load
- Network connectivity issue mid-generation

**How to handle:**
```ts
case "PERSONALIZATION_JOB_TIMEOUT":
  showMessage("Generation is taking longer than expected. Please try again.");
  tryOnButton.disabled = false;
  break;
```

**Tip:** Increase `pollMaxAttempts` in config if timeouts are frequent:
```ts
pollIntervalMs: 1500,
pollMaxAttempts: 200, // 5 minutes instead of 3
```

---

### `NETWORK_ERROR`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — check connection and retry |
| When | Network request failed |

**Causes:**
- User lost internet connection
- Backend server is down
- CORS misconfiguration (in full-stack mode)

**How to handle:**
```ts
case "NETWORK_ERROR":
  showMessage("Network error. Check your connection and try again.");
  break;
```

---

### `SELECTION_FAILED`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — try different photos |
| When | Photo processing failed during `ingestImages()` |

**Causes:**
- Corrupt or unreadable image files
- Browser ran out of memory processing many large photos
- face-api.js models failed to load

**How to handle:**
```ts
case "SELECTION_FAILED":
  showMessage("Could not process photos. Try uploading different ones.");
  break;
```

---

### `AUTH_DOMAIN_NOT_ALLOWED`

| Property | Value |
|---|---|
| Recoverable | ❌ No |
| When | The requesting domain is not authorised for this public key |

**Causes:**
- Brand's public key (`gn_pk_...`) is not configured for this domain
- Using a public key from a different brand/environment

**How to handle:**
```ts
case "AUTH_DOMAIN_NOT_ALLOWED":
  // Developer error — register your domain for this key in the Gennoctua dashboard
  console.error("Domain not authorised for this public key");
  break;
```

---

### `PRODUCT_CONTEXT_NOT_FOUND`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — pass product info explicitly |
| When | SDK could not detect product info from the page and no overrides were provided |

**How to handle:**
```ts
case "PRODUCT_CONTEXT_NOT_FOUND":
  // Pass imageUrl and productType explicitly to sdk.personalize()
  break;
```

---

### `PRODUCT_TYPE_NOT_FOUND`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — provide productType |
| When | `productType` was not provided and could not be inferred |

**How to handle:**
```ts
case "PRODUCT_TYPE_NOT_FOUND":
  // Always pass productType explicitly to sdk.personalize()
  break;
```

---

### `REQUIRED_USER_IMAGE_MISSING`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — ask user to upload photos |
| When | No uploaded photo matches the required category for the product |

**Causes:**
- User hasn't uploaded any photos yet
- User uploaded only face photos but a full-body photo is required (e.g. clothing)
- User uploaded only room photos but a person photo is needed, or vice versa

**How to handle:**
```ts
case "REQUIRED_USER_IMAGE_MISSING":
  showUploadPrompt("Please upload a suitable photo to try on this product.");
  break;
```

---

### `UPLOAD_FAILED`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — retry upload |
| When | Image upload to storage failed during `ingestImages()` |

**How to handle:**
```ts
case "UPLOAD_FAILED":
  showMessage("Photo upload failed. Please try again.");
  break;
```

---

### `TAGGING_FAILED`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — SDK falls back silently |
| When | LLM profile-refinement step failed |

This error is non-fatal — the SDK silently falls back to the local AI picks when tagging fails. You will typically only see it via `sdk.on("error", ...)`.

---

### `PERSONALIZATION_CANCELLED`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — user can retry |
| When | Request was cancelled via `AbortController` or `sdk.cancel()` |

**How to handle:**
```ts
case "PERSONALIZATION_CANCELLED":
  // No action needed — user initiated the cancel
  enableTryOnButton();
  break;
```

---

### `CACHE_ERROR`

| Property | Value |
|---|---|
| Recoverable | ✅ Yes — SDK operates without cache |
| When | IndexedDB read or write failed |

**Causes:**
- Browser in private/incognito mode with storage blocked
- IndexedDB quota exceeded
- Browser does not support IndexedDB

The SDK continues normally when cache errors occur — results are simply not persisted.

---

### `UNSUPPORTED_BROWSER`

| Property | Value |
|---|---|
| Recoverable | ❌ No — requires a modern browser |
| When | Required browser APIs are unavailable |

**Causes:**
- Very old browser without WebAssembly or Canvas support
- Restricted browser environment

**How to handle:**
```ts
case "UNSUPPORTED_BROWSER":
  showMessage("Your browser does not support virtual try-on. Please use a modern browser.");
  break;
```

## Handling All Errors

A complete error handler:

```ts
import { SDKError } from "@gennoctua/personalize-core";

async function runTryOn() {
  try {
    const result = await sdk.personalize({
      imageUrl: productImageUrl,
      productType: "sunglasses",
      gender: "female",
    });
    showResult(result.imageUrl);
  } catch (err) {
    if (!(err instanceof SDKError)) {
      // Unexpected error
      showMessage("An unexpected error occurred.");
      console.error(err);
      return;
    }

    switch (err.code) {
      case "AUTH_INVALID":
        showMessage("Session expired. Refreshing...");
        // SDK auto-retries in publicKey mode
        break;

      case "RATE_LIMITED_CLIENT":
        showMessage("Please wait before trying again.");
        setTimeout(() => enableTryOnButton(), 10000);
        break;

      case "RATE_LIMITED_SERVER":
        showMessage("Servers are busy. Try again in a minute.");
        break;

      case "PERSONALIZATION_JOB_FAILED":
        showMessage("Generation failed. Try a different photo.");
        enableTryOnButton();
        break;

      case "PERSONALIZATION_JOB_TIMEOUT":
        showMessage("Taking too long. Please try again.");
        enableTryOnButton();
        break;

      case "NETWORK_ERROR":
        showMessage("Network error. Check your connection.");
        enableTryOnButton();
        break;

      default:
        showMessage("Something went wrong. Please try again.");
        if (err.recoverable) enableTryOnButton();
        break;
    }
  }
}
```

## Listening via Events

Instead of try/catch, you can use the event bus:

```ts
sdk.on("personalization:failed", ({ error, code }) => {
  handleError(code, error);
});

sdk.on("error", (err) => {
  console.error("Unhandled SDK error:", err.code, err.message);
});
```

## `SDKError` Type

```ts
class SDKError extends Error {
  code: string;         // one of the codes above
  message: string;      // human-readable description
  recoverable: boolean; // true if the user can retry
  details?: unknown;    // additional debug info
}
```
